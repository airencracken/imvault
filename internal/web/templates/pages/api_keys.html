Uploading from a script

curl -H "Authorization: Bearer $IMVAULT_KEY" \
     -F "files=@photo.jpg" \
     {{.BaseURL}}/api/v1/upload

Add -F "public=1" to make the upload shareable, and -F "album=summer-2026" to drop it into an album. Uploads made through the API are private by default.

Albums and tags

# Create an album and add two uploads to it
curl -H "Authorization: Bearer $IMVAULT_KEY" -H 'Content-Type: application/json' \
     -d '{"title":"Summer 2026","public":true}' \
     {{.BaseURL}}/api/v1/albums

curl -H "Authorization: Bearer $IMVAULT_KEY" -H 'Content-Type: application/json' \
     -d '{"files":["abc123","def456"]}' \
     {{.BaseURL}}/api/v1/albums/summer-2026/files

# Tag a file, then find everything carrying that tag
curl -H "Authorization: Bearer $IMVAULT_KEY" -H 'Content-Type: application/json' \
     -d '{"name":"beach"}' \
     {{.BaseURL}}/api/v1/files/abc123/tags

curl -H "Authorization: Bearer $IMVAULT_KEY" \
     '{{.BaseURL}}/api/v1/files?tag=beach&kind=image'

Write endpoints accept either JSON or ordinary form encoding, and albums can be addressed by slug or numeric id.

Plain-text responses

ShareX and similar tools expect a bare URL. Append ?format=text to an upload and the response is one URL per line, or send Accept: text/plain.

Endpoints

MethodPathPurpose
GET/api/v1/meIdentify the key
POST/api/v1/uploadUpload one or more files
GET/api/v1/filesList and filter your uploads
GET/api/v1/files/{id}Metadata for one file
PATCH/api/v1/files/{id}Change visibility
DELETE/api/v1/files/{id}Delete a file
POST/api/v1/files/{id}/tagsAttach a tag
DELETE/api/v1/files/{id}/tags/{tag}Detach a tag by id, slug or name
GET/api/v1/tagsList tags you can see
GET/api/v1/albumsList your albums
POST/api/v1/albumsCreate an album
GET/api/v1/albums/{ref}Album with its files
PATCH/api/v1/albums/{ref}Update title, description or visibility
DELETE/api/v1/albums/{ref}Delete an album (files are kept)
POST/api/v1/albums/{ref}/filesAdd files to an album
DELETE/api/v1/albums/{ref}/files/{id}Remove a file from an album

{ref} is an album slug or numeric id. Keys act as the account that owns them and can only ever reach their owner's files and albums.
