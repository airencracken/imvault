# Imvault 0.10.1

Fixes sign-in, mail and OpenRC configuration problems found in an audit.

## Changes

- Password reset and OpenID Connect sign-in now ask for the account's TOTP code
  or a recovery code before signing in.
- Changing a password ends the account's sessions, open reset links and pending
  two-factor attempts together. A failed reset leaves the link usable.
- Imvault always keeps at least one enabled administrator, even when removals,
  demotions or disables happen at the same time.
- SMTP STARTTLS no longer falls back to plain text. Timeouts cover every step
  of talking to the relay. Lines starting with a dot arrive intact.
- OpenRC configuration is installed with mode 0600, including by the Gentoo and
  Alpine recipes. Reinstalling from source tightens existing files and keeps
  your settings.

## Upgrade notes

Back up before upgrading. There is no database migration.

Accounts with two-factor authentication now see the code prompt after a
password reset or provider sign-in. If someone has lost both their second
factor and their recovery codes, an administrator can clear it.

For a local mail relay without encryption, set `IMVAULT_SMTP_TLS=none`. The
default, `starttls`, requires TLS.

On an existing OpenRC install, run `chmod 0600 /etc/conf.d/imvault`. If SMTP
credentials sat in a world-readable file on a shared host, change them.

The upgrade does not end existing sessions. To cut off sessions and reset links
issued by an older version, change your password after upgrading.

See [installation and upgrades](../releases.md).
