# Imvault 0.11.0

Optional Linux confinement with Bubblewrap. Nothing changes until you turn it
on.

- `imvault sandbox` starts the server with a restricted filesystem, its own
  process namespace and private temporary storage. HTTP and outbound network
  access still work.
- `imvault sandbox --check` tests the policy without starting the server or
  creating a database.
- OpenRC supports `IMVAULT_SANDBOX=true`. The systemd setup is documented,
  including the override its hardened unit needs.
- Shutdown signals reach the server. Bad mounts, missing Bubblewrap,
  unavailable namespaces and setuid Bubblewrap all fail with a clear error.
- Secrets stay in the server's environment, never on Bubblewrap's command line.
  Unrelated environment variables are dropped.
- `IMVAULT_MEDIA_SANDBOX=true` separately confines ffmpeg and ffprobe to one
  input file and private scratch space, with no network or credentials.
- Symlinks in media output are rejected.

There are no schema changes. Back up as usual before upgrading. Install a
current, non-setuid Bubblewrap and check namespace support as the service
account before enabling it.

See [Linux confinement](https://github.com/airencracken/imvault/blob/v0.11.0/docs/sandbox.md)
for setup, custom paths and limits.
