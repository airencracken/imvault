# Imvault 0.13.0

A quieter, safer starting point for a family photo library, with public house
rules and backups that no longer need an interruption.

## Before you upgrade

- Back up with the old binary before replacing it. Existing saved policies and
  explicit configuration remain in effect. Unconfigured defaults now require
  invitations and reject anonymous uploads; Docker Compose follows these defaults.
- Images are capped at 24 megapixels before decoding, and uploads default to
  one at a time regardless of CPU count. Increase concurrency deliberately if
  your host has room. Existing larger images remain accessible.
- HTTPS base URLs force secure cookies, even if the cookie setting says false.
- Account exports need temporary disk space for a complete ZIP before sending
  it. Set `TMPDIR` if the system temporary directory is too small.
- There is no new database migration in this release.

## Changes

- **About & house rules** names active administrators and moderators and shows
  the public contact details and rules saved in Admin Settings. Private labels
  explain that these staff can see private files too and link to that page.
- Closed registration offers **Have an invitation?** on the home and sign-in
  pages. Invitation codes still work when public registration is closed.
- Verified backups use a SQLite snapshot and pin object deletion while copying;
  browsing and uploads continue. Older running servers are refused.
- `backup --output-dir DIRECTORY` creates a uniquely named snapshot. Native
  systemd packages include an optional daily backup timer; a cron example is
  shipped for OpenRC hosts. Neither is enabled automatically. Create a private
  destination, enable one scheduler, and manage retention and off-host copies.
- Root-run backups resolve the installed service's storage and encryption
  settings before switching to its account, including custom disk and S3 paths.
- Failed exports return an error before successful download headers. ZIPs are
  prepared one at a time and their temporary files are cleaned up.
- The file view counter is removed and browsing no longer increments it.
  Legacy stored counts and the API field remain for compatibility.

See [operations](../operations.md) for timer and cron setup, storage overrides,
retention and recovery drills.
