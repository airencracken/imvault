# Imvault 0.10.0

Better photo locations, separate location sharing, and tagging in bulk.

## Changes

- Imvault recovers valid JPEG GPS data even when another part of the EXIF is
  damaged. Older photos refresh from the stored original when you open them or
  fetch them through the API.
- A **Location** section shows coordinates and an OpenStreetMap link. Owners
  see an explanation when the original has no readable GPS. Set
  `IMVAULT_MAP_URL` and `IMVAULT_MAP_KEY` for an optional static map.
- Location sharing is now separate from EXIF on uploads, photos and albums, in
  the browser and the API. An album can hide either one, but never reveals what
  a photo hides.
- Select several photos in **Your gallery** and add comma-separated tags to all
  of them. Existing tags stay. The API equivalent is `POST /api/v1/files/tags`;
  if any photo fails, nothing changes.

## Upgrade notes

Back up the database and stored objects before upgrading; startup migrates the
database. Existing photos and albums start with Location set to **Follow
EXIF**, so their GPS sharing stays the same. Originals are untouched; there is
no need to re-upload.

**Hidden EXIF now hides camera and date on the photo page too**, as it already
did for downloads. Owners and administrators still see everything. To share
camera details without GPS, choose EXIF **Shown** and Location **Hidden**.

JPEG, PNG and WebP downloads can keep EXIF and GPS separately. Mixed settings
also remove XMP, maker notes and embedded thumbnails. Video downloads drop all
container metadata when either setting is hidden. Formats that cannot be
filtered safely are not offered for download until both settings allow the
original.

If the original has no readable GPS, there is nothing to recover. Some phone
export and sharing options strip GPS even when the phone's library shows it;
the owner explanation helps tell that apart from hidden data or a read error.
