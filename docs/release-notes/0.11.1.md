# Imvault 0.11.1

Let trusted members invite people. In **Admin → Users**, choose **Allow
invites** for a member. Their account shows a **can invite** badge, and
**Invitations** appears in their navigation on their next page load. This is
separate from their role. Members see, create and revoke only their own codes.
New accounts do not inherit the permission.

- Forms keep what you typed when validation fails. One-time codes and links
  are never cached.
- Revoking a code asks for confirmation.
- The invitations page reflects the actual registration policy.
- Imvault checks the issuer's current permission, and whether their account is
  disabled, every time a code is created or revoked.
- Codes from a disabled issuer stop working until the issuer is enabled again.
  Removing someone's invite permission leaves their existing codes active;
  revoke those separately.
- Provider sign-ups now record which invitation was used, as password sign-ups
  already did.

There are no schema changes. Back up as usual before upgrading.

See [invitations](https://github.com/airencracken/imvault/blob/v0.11.1/docs/accounts.md#invitations)
for details.
