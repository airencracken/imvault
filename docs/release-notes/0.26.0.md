# Imvault 0.26.0

Unreleased.

## Camera details and location are two plain choices

Each file now has two switches, under **Edit** on its page: show camera details,
and show location. Both start hidden on public uploads and shown on
members-only and private ones. Making a file public hides both again.

The old **Follow visibility** and **Follow EXIF** settings are gone, and albums
no longer have metadata settings.

### What the upgrade does

On first start, Imvault works out what other people could see of each file
under the old settings and saves that as the file's two choices. It applies
the strictest answer: the file's own settings, what they followed, and any album
the file was in that hid camera details or location. Nothing becomes more
visible than it was. A file that only hid its location because of an album
keeps it hidden after leaving that album; show it again from the file's page.

Back up the stopped data directory before upgrading and keep that pre-upgrade
snapshot. Older binaries cannot open the upgraded database.

### API changes

- `metadata` and `location` on files are now `shown` or `hidden`. `true` and
  `false` are accepted on input. `inherit` is rejected.
- Changing `visibility` to `public` hides both unless the same request sets them.
- Albums no longer return `metadata` or `location`. Sending either to an album
  endpoint is an error.

See [the API guide](../api.md#camera-details-and-location).

## Metrics no longer track people or files

The admin metrics page shows site totals only. Imvault stopped recording who
signed in and which files each member opened, and the upgrade deletes the
sign-in and view history it had stored. Counts of accounts, files and storage
are unchanged.
