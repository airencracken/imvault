# Imvault 0.26.0

Simpler sharing controls, calmer pages and colour palettes. Read
**Before upgrading** first.

## Camera details and location are two plain choices

Each file has two switches under **Edit** on its page: show camera details, and
show location. Both start hidden on public uploads and shown on members-only
and private ones. Making a file public hides both again.

The **Follow visibility** and **Follow EXIF** settings are gone, and albums no
longer have metadata settings.

On first start, Imvault saves what other people could see of each file under
the old settings, using the strictest answer from the file and any album it was
in. Nothing becomes more visible. A file that only hid its location because of
an album keeps it hidden after leaving that album; show it again from the
file's page.

## Pages put your photos first

- A photo's page shows its details, tags, albums and links first. Rotate,
  rename, description and sharing sit behind **Edit**, and deleting your own
  file is called **Move to Trash**.
- The gallery has one search row; sorting and dates sit behind a disclosure.
  The organise panel appears once you tick a photo.
- The albums page lists your albums before the **New album** form.
- Errors appear on the site's own page in plain words.
- A **Skip to content** link and current-page marks help keyboard and screen
  reader users.

## Colour palettes

Pick **Slate** (the default) or **Sage** from the theme menu, next to System,
Light and Dark. Owners can set the site palette under instance settings. Your
saved light or dark choice carries over.

## Passwords

New passwords need at least 12 characters. Existing passwords keep working.

## Metrics show site health, not people

The admin metrics page shows requests, errors, response times and data served
per route, plus counts of failed sign-ins, rate-limited attempts and rejected
links. Imvault no longer records who signed in or which files anyone opened,
and the upgrade deletes the sign-in and view history it had stored.

## Before upgrading

Back up the stopped data directory before upgrading and keep that pre-upgrade
snapshot. The upgrade rewrites file sharing settings and removes the old
per-account analytics, so older binaries cannot open the upgraded database.

## For operators

- The browser now refuses inline scripts: the Content-Security-Policy is
  `script-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`.
  A proxy that injects inline scripts into pages will stop working.
- Album discussions that are not configured log which of `IMVAULT_BASE_URL` or
  `IMVAULT_WITMOOT_URL` is missing. Members see "Discussions aren't set up on
  this site yet."
- `/account` redirects to `/settings/account`.
- The settings page shows "The last backup failed. Check the server log."
  instead of the raw backup error.

## For API clients

- `metadata` and `location` on files are `shown` or `hidden`. `true` and
  `false` are accepted on input; `inherit` is rejected.
- Changing `visibility` to `public` hides both unless the same request sets them.
- Albums no longer return `metadata` or `location`; sending either to an album
  endpoint is an error.

See [the API guide](../api.md#camera-details-and-location).

## Shared code

Imvault now uses Comfylib 0.7.1: site health metrics and security counters,
the shared palettes, theme script and picker, error pages, password rule, copy
buttons, backup summary and size formatting.
