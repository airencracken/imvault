# Imvault 0.12.0

A hardening release. It fixes defects found in an audit, several of which
leaked location data or allowed sign-in to the wrong account. Sandbox, service
configuration, mail and proxy handling now come from Comfylib, the library
Imvault shares with Witmoot.

## Before you upgrade

- **Back up first, with 0.11.1.** Startup migrates the database, and an older
  binary now refuses a newer database, so going back means restoring that
  backup. `imvault backup` no longer migrates.
- **Rename `IMVAULT_TRUST_PROXY_HEADERS` to `IMVAULT_TRUSTED_PROXIES`** and list
  your proxy's addresses: `127.0.0.1/32,::1/128` for a proxy on the same host,
  or the proxy's address for one in another container or host. The old name
  stops startup whatever its value, even `false` or empty. The Gentoo package
  renames it for you. The Debian package does not edit
  `/etc/imvault/imvault.env`, so rename it there by hand.
- **Settings are parsed strictly.** A boolean, number, size or duration Imvault
  cannot read now stops startup and names the setting. Before,
  `IMVAULT_ALLOW_SIGNUP=no` quietly left signup on.
- **Mail needs `IMVAULT_BASE_URL`.** Reset and confirmation links are built only
  from it, never from the request's Host header.
- **`IMVAULT_SMTP_FROM` must be one address**, optionally with a display name,
  on one line. A bad value stops startup even with no relay configured.
- **The OIDC issuer is used exactly as configured**, trailing slash included.
- **Everyone signed in over HTTPS is signed out once.** The session and CSRF
  cookies are now `__Host-imvault_session` and `__Host-imvault_csrf`. Plain-HTTP
  instances keep the old names and their sessions.

## Security fixes

- Location data no longer survives stripping. Imvault now removes data appended
  after a JPEG or GIF (depth maps, motion-photo clips, second images with their
  own GPS), unlisted metadata segments, and clip subtitle and data tracks such
  as drone GPS.
- Animated GIFs obey the same pixel limit as other images.
- A provider sign-in links to an existing account only if that account's email
  was verified. A domain allow-list requires the provider to have verified the
  address.
- The album API no longer shows other contributors' private files or hidden
  details.
- Sign-in redirects stay on this site.
- Anonymous uploads can no longer take every upload slot, and request bodies
  have time limits.
- Removing someone's invite access, or deleting their account, revokes their
  open invitations. Member invitations admit at most 25 people and last at most
  30 days.
- Form tokens are tied to the session. Turning on two-factor authentication
  ends other sessions, and the enrolment code cannot be reused to sign in.
- Accounts created through a provider can confirm at the provider, set a
  password, and cannot remove their last way in.
- Sign-up, password reset and password checks are rate limited. Reset mail goes
  out after the response, so timing does not reveal which accounts exist.
- Pages cannot be framed, and every response sends `nosniff`.
- Sent mail no longer leaves live links in the queue. Without a relay, Imvault
  no longer logs messages, so reset links stay out of the log. Administrators
  issue reset links from the admin pages as before.
- Maintenance commands run as root switch to the service account.

## Other changes

- **Going back.** An older binary, and every maintenance command, refuses to
  start against a database with migrations it does not know. Restore the backup
  from before the upgrade instead. See
  [going back to an older binary](../operations.md#going-back-to-an-older-binary).
  `imvault restore` refuses a backup from a newer Imvault.
- **Private data directory.** The systemd unit uses `StateDirectoryMode=0700`
  and `UMask=0077`. The OpenRC script requires mode 0700 and starts the server
  with umask 0077, so an existing `/var/lib/imvault` is tightened from 0750 on
  the next start. If a backup agent read the directory through the `imvault`
  group, run it as the service account instead.
- **Stopping.** systemd's `TimeoutStopSec` and OpenRC's stop retry are now 25
  seconds, longer than the server's 15-second drain. OpenRC refuses a relative
  `IMVAULT_BIN`, `IMVAULT_LOG_FILE` or `IMVAULT_DATA_DIR`, and reports a failed
  start when the server exits within a second.
- **Container health.** The image has a `HEALTHCHECK` that probes `/healthz` on
  `IMVAULT_ADDR`'s port. `/data` is created at mode 0700; an existing named
  volume keeps its mode until you run `chmod 0700` inside it.
- **Mail.** The sender is written in canonical form, so a display name may now
  appear quoted (`"Imvault" <no-reply@example.com>`). `IMVAULT_SMTP_TLS` accepts
  only `starttls`, `implicit` or `none`.
- **Client addresses.** Behind trusted proxies, Imvault reads `X-Forwarded-For`
  from the right, skipping trusted proxies, and uses the first other address.
  An entry that is not a plain IP address falls back to the proxy's own
  address. `X-Real-IP` is ignored. `proxy-config` prints the new setting.
- **Rate limits** group IPv6 clients by /64. Each limiter tracks at most 10,000
  callers and forgets the least recently seen.
- **Sandbox.** `imvault sandbox --check` now runs the confined binary itself, so
  a policy that cannot start Imvault fails the check. `SSL_CERT_FILE` in the
  service environment now names the CA bundle the server trusts; it must be an
  existing regular file. On merged-`/usr` systems, `/bin`, `/lib` and similar
  links stay links. `--read-file` paths must be clean.
- **Commands run by hand** read systemd's `EnvironmentFile=` as systemd does: one
  literal path with an optional leading `-`. A value with a `%` specifier is
  refused with a hint to set `IMVAULT_DATA_DIR`. `-h`, `-help` and `--help` skip
  the switch to the service account.
