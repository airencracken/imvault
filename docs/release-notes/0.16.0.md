# Imvault 0.16.0 preparation

Explicit Witmoot discussions about albums. This version is prepared locally and
has not been published. Check the version against remote tags before publication;
the inspected checkout ends at v0.15.0.

An album owner can save or remove a link to an existing Witmoot discussion.
Signed-in people who can view the album can explicitly prepare a draft for a
new discussion or a reply in an existing one. The handoff includes only the
album link; it does not copy private album titles, descriptions, covers, image
counts or contents. Witmoot requires its own sign-in, destination choice and
normal posting action. No discussions or notifications are created automatically.

Configure `IMVAULT_WITMOOT_URL` and the canonical `IMVAULT_BASE_URL`. With the
optional per-member Witmoot/imvault connection, public albums can provide a
current title and public image count on request. The preview API requires an
authenticated key with album access and checks public visibility in the same
database statement that reads its metadata. Private or members-only albums
return 404; private/member files, expired files and videos are excluded from
the count. There is no public metadata endpoint or duplication of album contents.

See [album discussions](../discussions.md) for configuration and permissions.
Album browsing works if Witmoot is unavailable or never configured.

Stop the service and back up the complete data directory before upgrading.
Migration `030_album_discussions.sql` adds the discussion-link table. Run the
existing `imvault migrate` workflow as the service account, then restart.
Reverting an upgraded installation needs its pre-upgrade backup and old binary.
Comfylib v0.1.1 must be published with verified module checksums and the full
release checks must pass before tagging. No release tag has been created during
this preparation.
